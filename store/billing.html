Optional license integration

The default package is Free. It has no payment destination and makes no billing requests. Commercial builds are separate, require explicit local configuration and do not change the public Free downloads. This page documents the integration for maintainers.

Local processing

Collection archives, exact-file hashing, still-image conversion, saved workflows and source records run on the user’s device. They do not require a developer server, paid media API, cloud storage or paid compute. The optional merchant-of-record provider supplies hosted checkout and license validation. Its transaction fees are deducted from sales; registration, disputes or other provider fees may still apply. Do not promise that commerce has no costs.

Test configuration

  1. Create a Lemon Squeezy test product with one non-renewing upgrade variant and license generation enabled. Set the activation limit in the provider dashboard. Use no expiry for a perpetual local license.
  2. Copy billing.example.json outside the repository and replace the public store/product/variant IDs and original Share link containing /checkout/buy/. Do not use a customer’s single-use cart URL. Prices belong in the merchant dashboard and private launch plan, not public Free documentation.
  3. Build with node scripts/build.mjs --billing /path/to/test-billing.json. The testMode flag must match the provider’s actual environment; the build cannot inspect your merchant account.
  4. Use the provider’s documented test card, activate the receipt key in the extension and verify every licensed operation in a disposable profile.

An optional displayPrice string can be supplied in the private build configuration. The final charge and any applicable taxes are displayed at hosted checkout. No payment API credentials or card forms ship in the extension.

Activation and recovery

Activation preflights the configured store and product before consuming an instance. Validation binds the key, instance, active status, expiry, store and variant. Checks normally cache for 24 hours within a background session; a new session checks again. Network outages allow up to seven days after the last successful validation, bounded by expiry. Invalid or disabled licenses return to Free. Deactivation releases the instance before removing its local key. Lost profiles need merchant-assisted instance recovery.

One valid upgrade unlocks all local extras. Older signed test licenses remain compatible; there is no separate team tier. Browsing history and media are never sent in license requests. Provider replies may include customer information, but names and emails are not retained.

Refund handling

Process the refund and explicitly disable the license in the merchant dashboard. Do not assume every refund or chargeback revokes a key automatically. The next online validation sees the disabled status; existing offline grace may last up to seven days. No webhook server is deployed. Set the refund, activation and update terms before enabling sales.

Before a commercial release

A merchant account, real product configuration, customer support contact and an actual merchant-controlled purchase/refund test are required. Tests in this repository use a deterministic provider; they do not certify a live checkout. A merchant-configured Firefox build declares authentication-information transmission, and its store/privacy disclosures must match that build. The public Free package continues to declare no collection.
