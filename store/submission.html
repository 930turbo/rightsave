Publishing RightSave

The public release is the free local edition. It has not been submitted to either browser store.

Firefox

  1. Create a Mozilla Add-ons developer account.
  2. Create API credentials and supply WEB_EXT_API_KEY and WEB_EXT_API_SECRET through your local secret manager or environment. Keep secrets out of Git and chat.
  3. Run npm ci, npm run build, npm test, and npm run lint:firefox.
  4. When ready for an actual upload, run npm run sign:firefox. The default channel is unlisted; signed XPIs download into dist/signed.

Only a successfully downloaded Mozilla-signed XPI is suitable for ordinary permanent installation. Keep the add-on ID stable.

Chrome

  1. Register a Chrome Web Store developer account and complete registration directly.
  2. Build and package, then upload the Chrome ZIP in the Developer Dashboard.
  3. Use listing.txt, review-notes.txt and assets/ for the listing, permission explanations and screenshots.
  4. Review the actual version and identity details, then submit when ready. Approval is not assured.

Licensing

The default build has no Pro bypass and no configured signing public key. A licensed build requires an explicit public verification key. Private signing keys never ship. Pro checkout and contribution URLs stay empty until the maintainer connects real destinations.
