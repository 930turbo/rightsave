RightSaveDownloads

Privacy

Updated October 21, 2026, for RightSave 5.1. RightSave saves files on your device. It has no account system, checkout, license checks, advertising or analytics. The developer does not receive your media, page lists or troubleshooting summaries. Previews and downloads contact the original media hosts, which can see those requests and your IP address.

Reading a page

RightSave scans media on webpages you use. Enhanced social-site detection is on by default. On supported sites it reads media fields from selected API or GraphQL responses the page already requested. It does not make extra platform API requests or read request bodies. Raw response text is processed transiently, with a 2 MiB response limit and two concurrent readers. Only extracted media URLs, short labels, dimensions, posters and post links enter a bounded page cache.

Page caches clear on detected route changes, feature opt-out, site exclusion and document closure. Explicit scans also read visible and lazy-loaded media, CSS images, embedded JSON, Open Graph and JSON-LD. Turn off enhanced detection in Settings if you prefer ordinary page scanning.

What stays in this browser

Preferences, dismissed tips and explicitly saved workflows use browser local storage. Workflows contain filters, search text, preview size and naming rules; they do not contain a saved page history. Delete a workflow in the library. Temporary libraries, source page URLs, observed video URLs and download bookkeeping use session storage. A library’s stored list clears when its source tab or library tab closes. Older lists also expire during cleanup after two hours. The browser keeps its own download history separately.

Optional direct-video request detection starts disabled. With permission, it observes video response URLs and content types, not bodies. These URLs clear on source navigation, tab closure, permission removal or browser restart. Excluded sites are skipped. Clear temporary media lists in Settings to discard saved scans immediately. Existing open libraries may still display their in-memory list until you close them.

Files you choose to export

ZIP files, image conversion and duplicate comparisons run locally. ZIP contents stay in memory until saved. Conversion removes image metadata and animation. Copy link writes the exact selected URL to the clipboard only when clicked; signed links may contain access tokens and should be kept private.

Source lists and optional CSV/JSON records remove URL credentials, query strings and fragments. Paths, labels and filenames can still reveal private posts or content. These are source records, not restorable download queues. Exported workflow packs contain your chosen settings. Treat these files as private when appropriate. No file is automatically uploaded.

Troubleshooting summaries are prepared only when requested and show extension/browser versions and a small set of settings. They omit page addresses, media URLs, filenames, accounts and browsing history. You choose whether to copy or share them.

Permissions

Website access finds media and restores right-click across sites. Menus adds the browser submenu; downloads opens Save As; scripting scans accessible frames; storage keeps preferences and temporary lists. Firefox’s cookies permission passes the appropriate container ID to its download manager. RightSave never reads cookie values. ZIP and conversion cannot use Firefox container sessions; use individual saves there. Optional webRequest supports direct-video URL detection and is not required for normal saving.

The Firefox package declares no developer data collection. There is no remote executable code, third-party runtime SDK or developer backend. Following a GitHub, privacy or support link opens that site under its own policies.

Questions

Use GitHub Issues for general questions. Do not include private media, signed links, cookies or other account details in public reports.
